# Roadmap / План развития

Studio3D is built stage by stage; every stage ends with a version that runs in a real studio.
Stages 1–3 are fixed. The planned blocks below are not ordered yet — the order is decided when a block is
broken down into tasks.

Studio3D делается по этапам: каждый заканчивается версией, которая работает в настоящей студии.

## CRM

**Клиенты**
- Тип клиента: юрлицо, ИП, самозанятый, физлицо — от типа зависят документы.
- Реквизиты для документов: ИНН, КПП, ОГРН/ОГРНИП, юридический адрес, банк, БИК, расчётный счёт.
- Контактные лица (несколько у одного клиента): телефон, Telegram, Max, e-mail, «где общаемся».
- Заметки и теги («постоянный», «опт»).
- Импорт клиентов из Excel для старта.

**Заказы**
- Карточка заказа: номер, клиент и контактное лицо, описание, количество, срок, цена, ответственный.
- Несколько изделий в заказе, у каждого — материал и цвет (на этапе склада — привязка к реальным катушкам).
- Принтер в заказе не выбирается: принтер и катушка привязываются при запуске печати, задания печати
  попадают в заказ автоматически (одну партию можно печатать на нескольких принтерах).
- Файлы заказа: проект OrcaSlicer (.3mf), G-code, STL, фото и макеты клиента; новая версия не затирает старую.
- Закрывающие документы: чеки, договоры, счета, акты — прикрепляются к заказу.
- Журнал заказа: смена статусов, комментарии, кто и когда.

**Канбан (лучшее из Agile)**
- Доска заказов: колонки — статусы, карточки перетаскиваются.
- Статусы настраиваются в админке. По умолчанию: Новый → На обсуждении → Ждёт оплаты → В очереди → В печати →
  Постобработка → Готов, ждёт выдачи → Выдан/отправлен → Закрыт; отдельно «На паузе» и «Отменён».
- Лимит на колонку (например, «В печати» не больше, чем принтеров).
- На карточке: срок, ответственный, чек-лист этапов (нарезать, напечатать, постобработка, упаковка).
- Подсветка просроченных заказов и заказов, которые долго стоят в одной колонке.

**Поиск**
- Одна строка по всему: номер заказа, клиент, телефон, ИНН, имя файла, номер чека.
  Пример: клиент потерял чек — находим заказ по телефону и отправляем чек заново.

## Деньги

- Калькулятор цены: пластик (вес из G-code × цена грамма катушки) + электричество (время × тариф) +
  амортизация принтера + постобработка, упаковка, наценка.
- Коммерческое предложение в PDF одной кнопкой.
- Оплаты: предоплата, остаток, долги клиентов; выручка и маржа по заказам и за период.
- Документы из шаблонов по реквизитам клиента: договор, счёт, акт / УПД; QR-код СБП в счёте.

## Склад

- Группы и позиции добавляются через админку: пластик, сопла, запчасти, расходники, готовые изделия.
- Катушка: тип (PLA, PETG, ABS, ASA, PA-CF, TPU…), цвет, производитель, диаметр, вес нетто и вес пустой
  катушки, остаток в граммах, место хранения, в каком принтере стоит.
- Автосписание: после печати вес из G-code списывается с катушки этого принтера; при отмене — фактический
  расход по метрам нити и плотности.
- «Хватит ли пластика»: при запуске печати сравнение нужного веса с остатком и предупреждение.
- Расходники и запчасти: количество, минимальный остаток, уведомление при нехватке.
- Готовые изделия заказчиков: не забрали, напечатано сверх заказа, возврат. При новом заказе:
  «на складе 2, допечатать 3».
- Закупки: позиции ниже минимума попадают в список закупки; средняя цена грамма по фактическим закупкам.
- Наклейки с QR-кодами на катушки, коробки и изделия: сканирование телефоном — поставить в принтер,
  переместить, списать.
- Сушка пластика: когда катушку сушили, напоминания для гигроскопичных материалов (PA, PETG, TPU).

## Изделия

- Справочник изделий с «рецептом» печати: материал, сопло, профиль, файл, время, вес, фото эталона.
- Повторный заказ в один клик; готовые изделия на складе связаны со справочником.

## Производство

- Очередь печати и планировщик: система предлагает свободный принтер с нужным материалом и соплом;
  временная шкала загрузки; подсказка «эта печать закончится к утру».
- Что стоит в принтере: сопло и катушка. Проверка G-code учитывает их («нарезан под сопло 0,6, стоит 0,4»,
  «PA-CF без закалённого сопла»).
- Контроль брака по камере: локальная модель находит «спагетти» и отрыв детали, ставит на паузу, шлёт фото в бот.

## Бот и камеры

- Telegram-бот первым (работает без белого IP), Max — вторым модулем по тому же шаблону.
- Оператору: фото с камеры раз в N минут во время печати; старт, окончание, расчётное время; пауза и ошибки
  с пояснением; «ждёт снятия»; «пластик заканчивается»; нехватка расходников.
- Команды: `/status`, фото по запросу, пауза и отмена — только для разрешённых ролей.
- Бот отвечает только привязанным пользователям системы.
- Камеры: снимки по расписанию, живое видео, таймлапсы.
- Позже, отдельной опцией: уведомления клиентам («заказ готов»).

## Статистика

- Количество напечатанных изделий: по периодам, клиентам, изделиям, материалам.
- Расход пластика, брак и его причины, загрузка принтеров, время печати.

## Для клиентов

- Статус заказа по ссылке без регистрации: этап, ожидаемое время, фото готового изделия.
- Форма заявки / виджет для сайта: клиент загружает STL, видит примерную цену, заявка попадает в CRM.

## Ещё принтеры

- QIDI Q2, Elegoo Neptune 4 Max — после проверки на реальных принтерах; QIDI Plus 4 — довести проверку.
- Мастер подключения с автопоиском принтеров в сети.

## ТО

- Регламенты обслуживания по наработке и по времени, напоминания, журнал обслуживания.

## Устройства и расширения

- Собственные устройства студии по MQTT: умные розетки (точный учёт электричества), климат, датчик влажности
  в шкафу с пластиком.
- Расширения: новые модели принтеров и устройства пакетом, без правки кода.

## Надёжность

- Резервное копирование файлов заказов (G-code, 3mf) на внешнее хранилище, например Nextcloud по WebDAV.
- Персональные данные клиентов (152-ФЗ): согласие на обработку, разграничение доступа, журнал действий.
  Закладывается вместе с CRM.

## Распространение

- Английский интерфейс.
- Демо-стенд на синтетических данных (`python manage.py demo_data`).
- Установка одной командой.
