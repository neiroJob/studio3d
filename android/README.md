# Studio3D Android — оператор

Нативное приложение Kotlin + Jetpack Compose/Material 3. Android 8.0+ (API 26).
Обзор всех принтеров, карточка, снимки камер, время печати, история, неисправности и свет.
Push-уведомлений нет: по решению пользователя. Фонового наблюдения после закрытия приложения нет.
Состояние обновляется только при открытом приложении с интервалом 5/10/30 секунд; фото — вручную.
Команд запуска, паузы, отмены и нагрева нет. Демонстрация не подключается к оборудованию.

## Установка

1. Обновите сервер Studio3D из ветки main: `bash update.sh`. Миграция core 0012 добавляет мобильные сессии.
2. Скачайте APK из артефакта **Studio3D-Android** последнего успешного workflow **Android** на GitHub.
   В архиве также SHA256SUMS.txt. Для скачивания артефактов нужен вход на GitHub. Срок хранения — 30 дней.
   Debug-сборки разных CI-запусков подписываются разными ключами: при конфликте подписи удалите предыдущую
   внутреннюю сборку; для постоянного распространения потребуется стабильная release-подпись.
3. Установите APK на Android, разрешив установку из выбранного приложения загрузки при запросе системы.
   Сборка debug предназначена для внутренней проверки, не для публикации в магазине.
4. Введите адрес сервера, логин/пароль существующего аккаунта Studio3D. Нужны права просмотра дашборда;
   для света — существующее право управления печатью. Деактивация пользователя/отзыв прав прекращают доступ.
5. Для HTTP в локальной сети отдельно включите опцию на экране входа. Разрешены только частные IPv4,
   localhost и .local. Для внешнего адреса требуется HTTPS с доверенным сертификатом.

**Сейчас внешний HTTPS-адрес студии не настроен.** APK не создаёт внешний доступ самостоятельно.
Локальный адрес работает только из студии/сети с маршрутом к серверу. Перед проверкой через мобильный интернет
нужно согласовать и настроить внешний HTTPS-вход либо защищённый сетевой доступ. Принтеры и их камеры
напрямую в интернет не публикуются. Их адреса и ключи не передаются мобильному клиенту.

Если сервер не обновлён и `/api/mobile/v1/` отсутствует, приложение покажет пояснение, а не рабочие данные.
Проверка API в тестах не заменяет реальную установку приложения на телефон и проверку через внешний адрес.
K1C/WebRTC: кадр серверным клиентом ещё не подтверждён, при сбое будет явное сообщение «снимок недоступен».

## Сборка

Нужны JDK 17+, Gradle 8.11.1, Android SDK Platform 35/Build Tools 35.0.0.
Путь SDK задаётся стандартным ANDROID_HOME либо local.properties (не коммитится).

```bash
cd android
gradle assembleDebug testDebugUnitTest lintDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`. CI собирает тот же вариант и сохраняет отчёты.
Не коммитите SDK/Gradle-кеши, токены, локальные IP/пароли или ключи подписи.
Приложение не содержит учётных данных или фиксированного адреса студии.

## Данные и безопасность

- Пароль используется только для входа и не сохраняется.
- Сессия и последний снимок состояния шифруются ключом Android Keystore, резервное копирование отключено.
- В БД сервера хранится только SHA-256 случайного bearer-токена, срок 30 дней.
  Выход удаляет локальные данные всегда и отзывает сессию на сервере, если он доступен.
- Обычная веб-сессия не даёт доступ к мобильному API. Права проверяются при каждом обращении.
- При потере связи интерфейс показывает, что данные устарели; управление светом отключается.
- Камера передаётся сервером как JPEG с временем съёмки, HTTP-ошибка не подменяется картинкой.
- Никакой аналитики, Firebase, фоновой службы или разрешения на уведомления в приложении нет.

Серверный API v1: POST login/logout; GET fleet/events; GET printers/ID/history/photo;
POST printers/ID/light с JSON `{"on": true|false}`. Только bearer-аутентификация.
