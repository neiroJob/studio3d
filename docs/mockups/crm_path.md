# Путь заказа: клиент → заказ → печать → выдача

Описание к макету `crm_cards.html` (версия на согласование). В проект ничего не внесено, ждём ответа.

## Кто что делает

| Действие | Админ | Менеджер | Оператор |
| --- | --- | --- | --- |
| Создать клиента и заказ, менять изделия, цену, платежи | да | да | нет |
| Видеть клиента, цены, платежи, себестоимость | да | да | нет (заказ обезличен) |
| Менять статус заказа, отмечать этапы работ, комментировать, загружать файлы, отмечать напечатанное | да | да | да |
| Добавлять, убирать, переставлять этапы работ в общем списке | да | нет | нет |

## Путь

1. **Новый клиент.** Менеджер или Админ заводит карточку: тип (ИП, юрлицо, самозанятый, физлицо), реквизиты, контактные лица, согласие на обработку данных. Клиента можно создать и прямо из экрана «Новый заказ».
2. **Заказ.** Создают только Админ и Менеджер. В форме: клиент, срок готовности, ответственный, комментарий. Затем изделия. Для каждого изделия:
   - пластик выбирается из склада (группа «Пластик»), рядом виден остаток;
   - файл печати выбирается из загруженных или загружается новый; время печати и вес одной штуки берутся из файла (G-code, как в карточке принтера) и при необходимости правятся вручную;
   - система считает расход (вес × количество) и время (время × количество) и предупреждает, если пластика на складе не хватает.
   
   При сохранении заказ получает статус «Новый», в журнал пишется запись, этапы работ копируются из общего списка, пластик резервируется на складе.
3. **Этапы работ.** Список общий для всех заказов и неизменный для менеджера и оператора: проектирование / создание 3D-модели → согласование модели / чертежа → в печати → распечатано → постобработка → упаковка → отправка. В заказе их только отмечают выполненными. Админ может добавить свой этап, убрать лишний, поменять порядок.
4. **Печать.** Задания с принтеров привязываются к изделиям заказа. Растёт прогресс «напечатано / заказано». Время и вес по факту берутся из задания на принтере.
5. **Склад.** После каждого завершённого задания фактический расход пластика списывается с катушки и из резерва заказа. Остаток на складе уменьшается, при падении ниже минимума позиция подсвечивается «мало».
6. **Постобработка, упаковка, отправка.** Отмечаются как этапы работ. Часы постобработки идут в себестоимость.
7. **Выдача.** Статус заказа «Выдан», затем «Закрыт» после полной оплаты. Платежи, остаток и маржа видны Админу и Менеджеру в течение всего пути.

## Что я предположил (подтвердите или поправьте)

- Названия этапов: «Проектирование / создание 3D-модели» и «Согласование модели / чертежа». Остальные пять взяты дословно.
- Изменения общего списка этапов касаются только новых заказов. В уже созданных заказах этапы остаются как были.
- Свободный пункт чек-листа, который сегодня может добавить любой сотрудник, убирается: этапы только из общего списка.
- Пластик резервируется при создании заказа, а списывается после каждого завершённого задания по фактическому расходу.
- Этапы «В печати» и «Распечатано» отмечаются вручную, как и остальные. Автоматически статус заказа и этапы по печати не меняются (это отдельная задача блока «CRM»).
- Один заказ может содержать изделия из разного пластика, у каждого изделия свой пластик и свой файл.

## Вопросы

1. Обязательны ли пластик и файл печати при создании заказа? Заказ, где печать не нужна (только проектирование), создаётся без них?
2. Резервировать пластик при создании заказа или только списывать по факту?
3. Менеджер видит список этапов, но не меняет его. Верно?
