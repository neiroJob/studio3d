## Нить

- На обоих K1C запрос API подтвердил `filament_switch_sensor filament_sensor`,
  `enabled=true`, `filament_detected=true`. В профиле проекта этот датчик отсутствовал.
- На Q1 Pro и Plus 4 найден `filament_switch_sensor fila`. Изначально `enabled=false`,
  `filament_detected=true`. По явному разрешению пользователя датчики включены только после проверки,
  что оба принтера в состоянии `standby`. Повторное чтение подтвердило `enabled=true`,
  интерфейс перестал показывать «датчик отключён». Сохранение настройки после перезапуска не проверено.
- На Q1 Pro пользователь подтвердил извлечение нити, затем её вставку. `fila` в обоих случаях
  оставался true. Hall-датчик при отсутствии нити давал около −0,56 мм, при наличии — 0,88 мм.
  Порог `min_diameter=0.3` прочитан из конфигурации реального устройства. Локальный профиль Q1 Pro
  переключён на Hall; неизвестное/некорректное значение не считается наличием нити. Реакция Hall включена
  штатной командой на свободном принтере по разрешению пользователя, API подтвердил `is_active=true`.
  Серверное отображение после исправления ещё не проверено; автопауза при обрыве во время печати не проверена.
- Повторная проверка исправленным кодом против реального API Q1 Pro:
  15:48:50 МСК — пользователь извлёк нить, `Diameter=-0.54965`, код: `present=false`, `enabled=true`;
  15:49:37 МСК — пользователь вставил нить, `Diameter=0.88360`, код: `present=true`, `enabled=true`.
  Принтер находился в простое. Для отсутствующей нити на этом же измерении отдельно моделировалась пауза:
  предупреждение появилось. Эта программная подстановка не считается реальной паузой устройства.
- Физическая проверка датчиков остальных принтеров ещё не выполнена. Plus 4 пока остаётся на `fila`:
  результат Q1 Pro нельзя автоматически переносить на другую модель без проверки.
- У K1 нативная телеметрия содержит `materialStatus`. Родной JS принтера показывает при этом флаге
  `Consumable not detected`. В исправлении проекта этот сигнал используется для предупреждения;
  нулевой/отсутствующий флаг не трактуется как доказанное наличие нити. Реальное срабатывание ещё не проверено.
- Текст предупреждения: «Датчик нити: нет нити в датчике — проверьте подачу пластика».
  Датчик не устанавливает причину: конец катушки, обрыв или извлечение человеком.

## Контрольная печать K1

Пользователь самостоятельно запустил `ugol_PETG_41m55s.gcode`.
Во время подготовки API сообщил `state=1`, непустое имя файла, `withSelfTest=3`.
На сервере появилась запись «Отменено, 0 мин», пока устройство проходило самопроверку.
Драйвер завершал активное задание при временном отсутствии `job` в состоянии `self_test`.
Ошибка воспроизведена отдельным тестом: до исправления тест получил `cancelled` вместо пустого списка событий.
В локальном исправлении самопроверка с тем же активным файлом сохраняет задание.
Нагрев в самопроверке также исключён из предупреждения о нагреве без печати.
Затем в серверном интерфейсе наблюдался статус «Печать» с именем контрольного файла.
Финальное завершение, увеличение часов печати и снятие изделия пока не подтверждены.

## Проверка кода

Начальный прогон: **84 passed, 4 failed**. Три падения — обращение к связанным неисправностям
у несохранённого `Printer`; четвёртое — нестабильное ожидание ошибки соединения вместо таймаута.
Исправлена работа с несохранённым объектом; ошибки соединения и таймаута проверяются раздельно
без зависимости от поведения закрытого порта Windows.

Добавлены/расширены проверки:

- датчик нити и подписка на его поля у Q1 Pro, Plus 4, K1C;
- сообщение и сохранение неисправности, отображение в карточке и «Требует внимания»;
- полный цикл Moonraker для Plus 4 в дополнение к Q1 Pro и K1C;
- одна запись истории, 600 секунд наработки и ожидание снятия;
- полный цикл K1 с самопроверкой без ложной отмены;
- предупреждение нативного K1 по `materialStatus` без выдуманного признака наличия нити.

Тесты с эмуляторами подтверждают логику кода; они не заменяют завершённую печать и физическую проверку датчика
на каждом реальном устройстве. Последние изменения кода на сервер во время активной печати не выкатывались.

Итог последнего полного прогона двух модулей принтеров: **107 passed**; ruff для изменённых Python-файлов
и `git diff --check` — без ошибок. XML-отчёт и исходные два измерения Q1 Pro сохранены как локальные артефакты сессии.

Источники по Hall: [код QIDI](https://raw.githubusercontent.com/QIDITECH/klipper/main/klippy/extras/hall_filament_width_sensor.py),
[штатные макросы Q1 Pro](https://raw.githubusercontent.com/QIDITECH/QIDI_Q1_Pro/main/config/gcode_macro.cfg).
Порог сравнивается строго (`Diameter > min_diameter`); штатные макросы включают датчики при старте печати
и отключают при паузе/окончании. Проект продолжает читать измерения Hall и при отключённой автопаузе.
