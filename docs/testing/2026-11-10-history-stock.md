# Проверка истории, склада и предупреждений

Дата: 10.11.2026. Исправления подготовлены в dev. Рабочий сервер не обновлялся,
прошивка и состояние печатающего Q1 Pro не менялись.

## Подтверждённые причины

- В интерфейсе Studio3D история Q1 Pro пуста.
- API самого принтера содержит 133 записи, включая активную и успешные завершения.
  Последняя завершённая запись 000083 содержит 32073.390672 с печати и статус completed.
- HTTP Date принтера показывает 03.10.2024. Сравнение этих дат с границей учёта
  Studio3D в 2026 году отбрасывало задания.
- Резервная синхронизация запрашивала since за последнюю минуту. В Moonraker этот
  параметр фильтрует начало, а не окончание, поэтому длительные задания выпадали.
- Кнопка снятия зависела только от отображаемого статуса finished. При error она
  скрывалась даже при сохранённом awaiting_removal.
- Складское предупреждение отсутствовало в условии включения в «Требует внимания».
- Hall сообщает Diameter около 1.91 и is_active=false. Обычный fila также enabled=false.
  В конфигурации Hall enable=false; PAUSE отключает сенсоры, RESUME включает.
  Каким именно действием сенсоры были отключены в этот раз, по одному снимку неизвестно.
  Пользователь подтвердил текущую печать и запретил её трогать.

## Изменения

- Постраничный отбор завершений локально по end_time, поправка часов по HTTP Date
  при разнице свыше 5 минут, периодическая сверка каждые 30 секунд.
- Поправка хранится в PrintJob.clock_offset_seconds, миграция printers 0006.
  Даты помечены как оценка, счётчик длительности не изменяется. Повторный импорт
  того же ID не сдвигает уже сохранённые даты и не создаёт дубль наработки.
- При переподключении ожидание снятия восстанавливается только для последнего
  неоценённого успешного задания, совпадающего с подтверждённым complete принтера.
  Ошибка не скрывает кнопку; оценённое задание не возвращается на стол при повторе события.
- Склад, часы, неисправности и отключённая реакция на отсутствие нити видны
  в «Требует внимания», с красным индикатором предупреждения.
- Складская единица выбирается из шт/г/кг. Старое нестандартное значение доступно
  при редактировании именно прежней записи, без автоматического изменения чисел.

## Проверки

- 120 тестов: история/драйверы/склад/автоматический учёт и новые регрессии прошли.
- После добавления проверки периодической сверки повторно прошли 8 целевых тестов.
  Эти числа описывают пересекающиеся прогоны и не складываются.
- Ruff, Django check и makemigrations --check --dry-run без ошибок.
- Исправленный драйвер чтением реального Q1 Pro нашёл 10 завершений за последние
  14 суток. Запись 000083 сохраняет 32073.390672 с. Календарное окончание по текущей
  поправке оценивается как 09.11.2026 18:59:29 UTC.
- Это чтение API, не восстановление рабочей БД. Для последнего нужен выпуск кода
  и миграция сервера в согласованный момент. При изменявшихся часах даты необходимо сверять.

## Предыдущая приёмка через сайт, 09.11.2026

Созданы явно тестовые позиции сопла, термоноска, пластика двух фирм, готового изделия
и контрольного PETG, катушки 750/1000 г, клиент, контакт, заказ. Остатки тестовые.
Проверены черновик прихода, приход, списание, инвентаризация, резерв заказа,
отклонение недостаточного остатка и несовпадения материала/катушки.
Сопла: 0 → черновик 0 → приход 5 → списание 4 → инвентаризация 3.
PLA: 750 → списание 50 → 700 г одновременно на катушке и в общей позиции.
Резерв контрольного заказа: 1 г, свободно 999 из 1000 г.

Проверка снятия K1C-1 выполнена по прямому указанию владельца с тестовым комментарием
о том, что фактическое качество не оценивалось. Пустой обязательный комментарий отклонён.
Согласованный тестовый файл после запуска на K1C-1 завершился ошибкой прошивки:
Unknown command PRINT_START и Must home xy axis first. Успешная контрольная печать,
физическое списание и выпуск после снятия по этому испытанию НЕ подтверждены.
Повторного запуска не было. Тестовые записи не являются достоверными реальными запасами.
