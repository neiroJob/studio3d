# Telegram оператора

Бот наблюдает за заданиями Studio3D. Автоматические сообщения: начало печати, завершение/отмена/прерывание,
пауза/продолжение, новые ошибки и сообщения об отсутствии нити, потеря/восстановление связи.
Во время печати отправляется фото и состояние каждые N минут. После завершения — напоминание снять изделие.
Для каждого чата можно выбрать принтеры. Выбор пуст — все, включая добавленные позже.

Управление ограничено включением и выключением света. Бот не запускает печать, не ставит её на паузу,
не отменяет задания, не нагревает принтер и не подтверждает снятие изделия. Для этого используется проект.

## 1. Создать бота

1. Откройте официальный [@BotFather](https://t.me/BotFather) в Telegram, отправьте `/newbot`.
2. Задайте название, например `Studio3D — оператор`, и свободное имя, оканчивающееся на `bot`.
3. В проекте откройте **Администрирование → Telegram**, введите токен в поле «Токен бота от BotFather» и нажмите «Сохранить». Затем нажмите **«Запустить бота»**.
4. Токен хранится в БД зашифрованным ключом, производным от SECRET_KEY, и повторно не показывается. Пустое поле сохраняет прежний токен. Для замены введите новый и сохраните; для удаления отметьте соответствующее поле. При утечке отзовите токен через `/revoke` у BotFather и замените здесь. Не публикуйте его и не отправляйте в чат поддержки.
5. Нужен отдельный бот для этой установки. Не подключайте тот же токен к другому сервису.
   Существующий webhook автоматически не удаляется: используйте другого бота либо отключите прежнюю интеграцию.

Бота создаёт владелец своего Telegram-аккаунта. До получения токена реальная доставка не может быть проверена.

После обновления с прежней версии токен из TELEGRAM_BOT_TOKEN больше не используется.
Один раз сохраните его в админке и нажмите запуск; старую переменную можно удалить из .env.

## 2. Обновить сервер

В папке проекта на сервере, в ветке `dev`:

```bash
git branch --show-current
bash update.sh
docker compose ps
docker compose logs --tail=50 bot
```

`update.sh` обновляет текущую ветку, собирает образ и пересоздаёт сервисы. Миграции применяет web при старте;
bot и collector запускаются после готовности web. Согласуйте обновление с оператором: перезапуск коллектора
временно прерывает наблюдение. Само обновление не посылает команд управления принтерам.

После однократного обновления проекта токен, запуск и остановка управляются из админки. Для этого больше не нужны изменения .env, команды терминала и перезапуск контейнера. «Остановить бота» прекращает получение команд и отправку сообщений; новые автоматические события во время остановки не накапливаются. Уже ожидающие сообщения сохраняются до следующего запуска с обычными ограничениями срока актуальности.

Фоновый сервис bot должен быть установлен и работать: в состоянии остановки он ждёт команды из админки. Изменение токена или запуска подхватывается каждые 5 секунд; прежние соединения отменяются и закрываются. Неверный токен или ошибка подключения показываются на странице. Автоматические уведомления включаются отдельной настройкой и не заменяют кнопку запуска. Сохраняйте прежний SECRET_KEY при переносе/восстановлении БД, иначе токен придётся ввести заново.

Сервис bot использует исходящие HTTPS-запросы к Telegram (long polling);
проброс портов, публичный домен и входящий webhook не нужны. Серверу нужен доступ к принтерам и их камерам,
Telegram API и исходящему UDP для WebRTC. Камеры не публикуются в интернете: сервер загружает JPEG в Telegram.

## 3. Добавить личный чат

1. В проекте откройте **Администрирование → Telegram**. Требуется право «Telegram, ИИ-провайдеры, расширения».
2. Нажмите «Добавить получателя», выберите тип «Личный чат сотрудника» и активного пользователя проекта
   с правом «Видеть дашборд и камеры». Задайте имя, выберите принтеры, сохраните.
3. Нажмите «Новый код». Код действует 10 минут, используется один раз; новый код отменяет предыдущий.
4. Передайте сотруднику ссылку с этой страницы. Он открывает её и нажимает «Запустить» в Telegram.
   Если имя бота ещё не появилось в проекте, можно отправить боту `/start КОД` вручную.
5. Нажмите «Тест» возле получателя. Проверка доступна до включения автоматических уведомлений.
   Дождитесь сообщения и результата «Отправлено» в журнале доставки.

Код — временный ключ доступа к выбранным принтерам; передавайте только адресату. В БД хранится хеш кода.
Имя Telegram не используется как доказательство личности. При деактивации пользователя проекта или отзыве
прав доступ к командам и новые доставки прекращаются. «Отвязать» запрещает доступ прежнему чату и отменяет код.

## 4. Добавить группу

1. Добавьте бота в нужную группу Telegram. У него должно быть право отправлять сообщения и фото.
   Администратором его делать не обязательно, если группа разрешает эти действия обычным участникам.
   При запрете добавления в группы настройте `/setjoingroups` у BotFather.
2. В проекте создайте получателя типа «Группа операторов», без пользователя, выберите принтеры.
3. Нажмите «Новый код» и отправьте **в нужной группе** `/pair@имя_бота КОД`.
4. Проверьте чат кнопкой «Тест». После преобразования группы в супергруппу с новым chat ID привяжите её заново.

Режим privacy в BotFather можно оставить включённым: используйте команды с `@имя_бота`.
Статус, фото и история доступны всем участникам привязанной группы. Учитывайте это при выборе её состава.
Для управления светом участник должен также привязать свой личный чат к пользователю проекта с правом
«Пауза, отмена, продолжение печати»; это существующее право управления принтерами, но бот использует его
только для света. Принтер должен быть разрешён и группе, и личному чату этого сотрудника.

## 5. Настроить уведомления

В админке включите автоматические уведомления, выберите личные чаты, группы либо оба варианта.
Задайте интервалы в минутах и нужные события. Интервал фото 0 отключает только периодические сообщения;
события продолжают работать. Интервал напоминаний 0 отключает повторы о снятии.
Задержка отсутствия связи помогает пропускать краткие переподключения; 0 означает сразу.
По умолчанию: фото каждые 10 минут, снятие каждые 30, отсутствие связи через 1 минуту.
Фото приходят только во время печати; пауза уведомляется отдельным событием.

У получателя «Получать автоматические уведомления» отключает только рассылку;
«Разрешить доступ» отключает также команды. Настройки отправки в личные чаты/группы ограничивают рассылку,
но не запросы из уже привязанных разрешённых чатов. `/mute` и `/unmute` меняют только личную подписку;
группой управляет администратор в проекте.

## Команды

| Команда | Что показывает |
| --- | --- |
| `/status` | Все разрешённые принтеры, статусы, прогресс и оставшееся время |
| `/status ID` | Файл, прогресс, время/оценка окончания, слой при наличии, температуры, нить и ошибки |
| `/photo ID` | Свежий JPEG и подробное состояние |
| `/alerts` | Принтеры, требующие внимания: ошибки, пауза, снятие, нет связи и нагрев в простое |
| `/history ID` | Последние пять заданий и результаты |
| `/hours ID` | Часы печати и включения |
| `/light ID on` / `/light ID off` | Только включение / выключение света, с проверкой прав и записью в журнал |
| `/mute` / `/unmute` | Отключить / включить мои автоматические сообщения |
| `/help` | Помощь |

ID берётся из `/status`; можно выбирать принтер кнопкой вместо ввода ID.
Оставшееся время — оценка из телеметрии/G-code, а не гарантия срока. Неизвестные показания так и обозначаются.
Имя файла передаётся без локального пути. Заказчики, цены, контактные данные и файлы проекта ботом не выдаются.

## Фото, очередь и диагностика

Поддерживаются JPEG/MJPEG-профили и нативный WebRTC Creality. Два одновременных получения кадров максимум;
один кадр может использоваться для нескольких получателей до 10 секунд. В подписи есть время снимка.
WebRTC ждёт до 35 секунд плюс закрытие соединения. Кадры не архивируются в проекте, отправленные фото
сохраняются в Telegram согласно настройкам этого сервиса. Если кадр получить нельзя, приходит текст
«Фото: …»; это доставка состояния, **не подтверждение исправности камеры**.

Docker bridge обычно объявляет принтеру адрес контейнера, недоступный из LAN. Для нативных WebRTC-камер
на **Linux-сервере** предусмотрен override с сетью хоста только для bot. Добавьте в серверный `.env`:

```dotenv
COMPOSE_FILE=docker-compose.yml:docker-compose.telegram-lan.yml
```

После `bash update.sh` bot получает LAN-интерфейс сервера. PostgreSQL/Redis для него публикуются только
на loopback сервера, порты 15432/16379 (при конфликте задайте `TELEGRAM_DB_PORT`/`TELEGRAM_REDIS_PORT`).
Остальные сервисы сохраняют обычную сеть Compose. Override предназначен для Linux; в Docker Desktop
сеть хоста требует отдельной поддержки/настройки. Для камер JPEG/MJPEG override не нужен.

Для WebRTC в пределах LAN STUN по умолчанию выключен. При необходимости маршрутизации задайте
`TELEGRAM_CAMERA_STUN=stun:ваш_сервер:порт` в `.env` и пересоздайте bot. Это не заменяет доступность
UDP между сервером и принтером. На 2026-11-03 прямое получение кадра с обеих K1C из тестовой среды
не подтверждено: ICE подключается, кадр не приходит. Проверка с сервера установки остаётся обязательной.

События и очередь хранятся в БД, переживают перезапуск bot. Старые импортированные задания не рассылаются.
Повторные события завершения одного задания не создают вторую запись. Есть повторы при сетевой ошибке,
задержка по ответу Telegram `retry_after`, ограничение частоты на чат. При блокировке бота/удалении из группы
получатель отключается: устраните причину, включите его и повторите тест.
Устаревшие периодические сообщения и напоминания пропускаются через 15 минут, остальные события — через сутки.
Напоминания о уже снятом изделии и периодические сообщения уже закончившейся печати также пропускаются.
Очередь не гарантирует доставку точно в секунду или без повторов: при потере подтверждения Telegram может
получить сообщение повторно. Отключение уведомлений в админке отменяет ожидающие доставки.

В админке видны имя бота, свежесть ответа сервиса, последняя ошибка и последние 30 доставок.
При проблемах:

```bash
docker compose ps bot
docker compose logs --tail=100 bot
```

Проверьте токен и кнопку запуска в админке Telegram, доступ в интернет, привязку и права получателя, режим рассылки,
подписку, наличие принтеров. Не публикуйте `.env`, токен или полные диагностические ответы Telegram.
Потеря связи с ботом не останавливает печать: он служит каналом наблюдения, а не системой аварийной защиты.
